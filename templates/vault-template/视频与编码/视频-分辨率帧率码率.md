## 一句话概要
> 视频三件套——分辨率=像素格子数（1920×1080 = 207 万像素）、帧率=每秒帧数（30/60 fps）、码率=每秒数据量（5 Mbps）。同分辨率帧率下，码率决定画质。码率控制三种方式：CBR / VBR / CRF。

# 视频三件套：分辨率 / 帧率 / 码率

## 1. 背景：为什么要学这个？

视频处理是 iOS / Android / Web 开发的**高频面试题**：
- 字节 / 腾讯 / 阿里 / 快手 的客户端岗位都常考
- 业务中"为什么我拍的视频上传后变模糊" 90% 是码率问题
- 不懂三件套 → 排查上传问题要走弯路

## 2. 核心概念

| 概念 | 含义 | 示例 |
|---|---|---|
| **分辨率** | 每一帧有多少个像素位置 | 1920 × 1080 ≈ 207 万像素 |
| **帧率** | 每秒播放多少帧画面 | 30 fps / 60 fps |
| **码率** | 压缩后每秒平均数据量 | 5 Mbps |

### 关键洞察

> 分辨率与帧率是"画面的骨架"，码率才是"画面的血肉"。

- 同样的分辨率 + 帧率，**码率不足会导致画质损失**（模糊、色块、块状伪影）
- **码率不直接决定画质**，还受编码格式、编码器效率、画面复杂度、压缩设置影响

## 3. 底层原理（面试加分项）

### 3.1 为什么码率不足会导致画质损失？

有损压缩（H.264/HEVC）的本质：**把信息丢掉，换体积小**。
- 块划分（Macroblock）→ 预测 → 量化（Quantization）→ 编码
- **量化步长**越大 → 丢得越多 → 压缩率越高 → 画质越差
- 码率 = 量化步长反相关：码率小 = 量化步长大 = 丢得多

### 3.2 码率控制三种方式

| 方式 | 特点 | 适用场景 |
|---|---|---|
| **CBR**（固定码率） | 每秒数据量尽量稳定 | 实时直播、低延迟传输 |
| **VBR**（可变码率） | 画面简单时少分配、复杂时多分配 | 本地视频压缩、文件存储 |
| **CRF / CQ**（质量目标） | 指定质量目标，编码器自行调整码率 | FFmpeg 转码、生成本地视频 |

> **为什么 VBR 比 CBR 画质好？** 同样文件大小下，VBR 把码率分配给"运动复杂的帧"（如爆炸、火焰），CBR 把码率平均分配——简单帧浪费码率、复杂帧画质崩。

### 3.3 码率五因素

1. **分辨率**（像素越多通常需更多数据）
2. **画面复杂度与运动程度**（静态容易压缩，快速运动难）
3. **编码器与编码格式**（H.264 vs HEVC，HEVC 通常低码率相近画质）
4. **画质要求**（保留更多细节需要更多数据）
5. **存储和网络限制**（本地 vs 实时传输）

### 3.4 为什么 HEVC 能"低码率相近画质"？

HEVC（H.265）相比 H.264 的关键改进：
- 编码树单元（CTU）从 16×16 扩到 64×64
- 帧内预测模式从 9 种扩到 35 种
- 运动矢量精度提升（1/4 像素 → 1/8 像素）
- 自适应环路滤波（SAO / DF）

**本质**：用更复杂的算法换压缩率。

## 4. 关键代码 / API

### 4.1 实际码率参考（H.264）

| 视频规格 | 起始参考码率 |
|---|---|
| 720p / 30 fps | 2–4 Mbps |
| 1080p / 30 fps | 4–8 Mbps |
| 1080p / 60 fps | 6–12 Mbps |
| 4K / 30 fps | 15–30 Mbps |

### 4.2 FFmpeg 转码命令

```bash
# CBR（固定码率，直播推流）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M -c:a aac -b:a 128k -x264-params "nal-hrd=cbr" output.mp4

# VBR（可变码率，文件存储）
ffmpeg -i input.mp4 -c:v libx264 -b:v 5M -maxrate 8M -bufsize 10M -c:a aac output.mp4

# CRF（质量目标，本地转码首选）
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -preset slow -c:a aac output.mp4
# CRF 18 = 视觉无损，23 = 默认，28 = 明显压缩
```

### 4.3 iOS AVAssetExportSession 设置码率

```swift
let preset = AVAssetExportPresetMediumQuality  // 中等画质
let session = AVAssetExportSession(asset: asset, presetName: preset)
// 或自定义码率：
let composition = AVMutableComposition()
let videoTrack = composition.addMutableTrack(withMediaType: .video, preferredTrackID: kCMPersistentTrackID_Invalid)!
let exportSession = AVAssetExportSession(asset: composition, presetName: AVAssetExportPresetHighestQuality)
exportSession?.fileLengthLimit = 50 * 1024 * 1024  // 限制文件大小 50MB
```

### 4.4 Android MediaFormat 设置码率

```java
MediaFormat format = MediaFormat.createVideoFormat(MediaFormat.MIMETYPE_VIDEO_AVC, width, height);
format.setInteger(MediaFormat.KEY_BIT_RATE, 5_000_000);  // 5 Mbps
format.setInteger(MediaFormat.KEY_FRAME_RATE, 30);
format.setInteger(MediaFormat.KEY_I_FRAME_INTERVAL, 2);  // GOP=2s
mediaCodec.configure(format, surface, null, MediaCodec.CONFIGURE_FLAG_ENCODE);
```

## 6. 面试回答模板

### Q1：分辨率和码率有什么区别？
> 分辨率是画面格子数（1920×1080 = 207 万像素），码率是每秒数据量（5 Mbps）。
> 同样分辨率下，码率低 = 画质差（块状伪影、色带）。
> 但码率不直接决定画质——还受编码格式、编码器、画面复杂度影响。

### Q2：为什么 H.265 能比 H.264 省一半码率？
> 编码块更大（CTU 64×64 vs 16×16）、帧内预测模式更多（35 vs 9）、运动矢量预测精度更高（1/8 vs 1/4 像素）、自适应环路滤波（SAO/DF）。
> 本质是"用更复杂的算法换压缩率"。
> 转码时 CPU 消耗也更高（H.265 编码约比 H.264 慢 2-5x）。

### Q3：CRF 和 CBR 怎么选？
> **CRF** 适合本地转码（ffmpeg），追求"质量优先、文件大小次要"。CRF 18 = 视觉无损，23 = 默认，28 = 明显压缩。
> **CBR** 适合直播推流，追求"网络稳定、延迟低"。
> **VBR** 适合点播文件，追求"文件小 + 画质好"。

### Q4：上传视频时码率多少合适？
> 看场景：
> - 移动端 4G 上传：≤ 5 Mbps（带宽限制）
> - WiFi 上传：≤ 10 Mbps
> - 短视频（< 30s）：2-5 Mbps
> - 长视频（> 5min）：4-8 Mbps
> 
> 实战经验：商品视频默认 2-3 Mbps，平衡画质和上传速度。

### Q5：iPhone 拍的 MOV 转 MP4，码率怎么变？
> iPhone 默认是 HEVC + PCM（高码率，约 30-50 Mbps for 4K）。
> 转 MP4 + H.264 + AAC 后：码率大幅下降（2-10 Mbps depending on quality），文件体积缩小 5-10x。
> 画质在低端设备上可能略降（HEVC 压缩效率更高），但兼容性大幅提升（MP4 + H.264 是最通用组合）。

## 7. 常见误区

| 误区 | 真相 |
|---|---|
| ❌ "分辨率越高越清晰" | 还要看码率。低码率高分辨率 = 模糊 |
| ❌ "帧率越高越流畅" | 人眼 24fps 就感觉连续，更高意义有限（且占带宽） |
| ❌ "码率高 = 画质好" | 编码格式和参数同样关键 |
| ❌ "CRF 0 = 最高画质" | CRF 0 是"无损量化"，但仍是 H.264 有损压缩，文件巨大 |
| ❌ "VP9 / AV1 兼容性好" | 实际上 H.264 兼容性最广，新编码部分老设备不支持 |
| ❌ "码率只跟分辨率有关" | 还跟画面复杂度、帧率、编码格式相关 |
